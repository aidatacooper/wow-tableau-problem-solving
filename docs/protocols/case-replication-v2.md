# WoW Tableau 单案例复刻协议 v2

更新时间：2026-07-29
状态：active

## 1. 目标

让 AI 从一篇 Workout Wednesday 相关文章和一个作者 Tableau 文件中：

```text
理解问题
→ 恢复 Tableau 解题链
→ 判断 cwtwb 能力缺口
→ 完整复刻主文件
→ 验证结果
→ 沉淀可复用能力
```

协议只规定长期通用流程，不记录任何具体案例。实际分析和输出全部放在
`iterations/<iteration-id>/`。

## 2. 基本单位

每次迭代固定处理：

```text
1 篇文章
+ 1 个主要作者 Tableau 文件
+ 1 份 iteration.md
+ 1 个可打开的复刻 TWBX
```

文章和 Tableau 文件必须一一对应。一个案例有多个附件时，只选择与文章解法
直接对应、角色为 `candidate_author_solution` 的主文件；其他文件只作为旁证。

## 3. 完成定义

“实现了若干底层能力”不等于案例完成。案例只有同时满足以下条件才能标记为
`replicated`：

1. 能用一句话说明原问题，以及普通做法为什么不正确；
2. 识别原文件中解决该问题所必需的 Tableau 语义；
3. cwtwb 生成一个独立 TWBX，覆盖完整的必要解题链；
4. 生成文件通过结构、保存重开、全量回归和 Tableau 语义验证；
5. 记录与原文件的必要差异，确认差异不改变问题答案。

只完成部分原语时状态为 `partial`，不得宣称已经解决或复刻该案例。

## 4. 问题理解

在查看 cwtwb API 之前，先回答：

| 项目 | 要回答的问题 |
|---|---|
| 问题 | 用户最终要得到什么判断、结果或交互？ |
| 直觉解法为什么失败 | 普通过滤、聚合或作图会遗漏或算错什么？ |
| 正确行为 | 完成后的 Tableau 文件必须表现出什么可观察结果？ |
| Tableau 解题链 | 数据域、参数、计算、视图、Dashboard 和动作如何共同产生结果？ |

文章用于解释“为什么”，原始 TWB 用于证明“怎么做”。视觉装饰只有在影响问题
表达或结果判断时才列为必要项。

## 5. 单次迭代

```text
锁定文章和主 Tableau 文件
→ 保存输入哈希
→ 写问题理解
→ 提取原文件的必要解题链
→ 用 cwtwb 完整复刻
→ 缺什么就补什么通用原语
→ 生成独立 TWBX
→ 测试和 Tableau 校验
→ 写 iteration.md
→ 回写 replicated / partial / blocked
```

一次允许实现多个能力，但它们必须都服务当前文件的完整复刻。不得顺带开发与
当前案例无关的能力，也不得用跨案例组合示例代替当前文件的复刻。

## 6. 迭代目录

```text
iterations/<iteration-id>/
├── iteration.md
├── evidence/
│   ├── source-lock.json
│   ├── workbook-inventory.json
│   └── validation.json
└── outputs/
    └── replicated-workbook.twbx
```

`iteration.md` 只包含：

1. 输入文章、case_id、workbook_id 和哈希；
2. 问题理解；
3. 原 Tableau 解题链；
4. cwtwb 实现与新增能力；
5. 复刻差异；
6. 验证结果和最终状态。

机器可读的长期状态写入 `usage/consumed-cases.json`，不把迭代文档当数据库。

## 7. 验证

每次复刻依次通过：

1. **结构**：XML、Schema、目标节点和依赖正确；
2. **Round-trip**：保存、重新打开、再次保存不丢失语义；
3. **分析器**：cwtwb 能识别新增能力；
4. **回归**：cwtwb 全量测试无新增失败；
5. **Tableau**：API 语义验证通过；必要时再做人工打开或截图检查；
6. **案例**：复刻文件满足“正确行为”中定义的可观察条件。

本地 XSD 通过不能代替 Tableau 语义验证。

## 8. 多次迭代的顺序

不预先规划很长的固定路线。每次完成后，从未消费案例中选择下一个，只比较：

1. 问题是否明确且可验证；
2. 所需能力是否能复用于其他案例；
3. 主 Tableau 文件是否完整、可解析；
4. 实现和验证成本是否适合单次完成。

默认优先顺序：

```text
语义正确性
→ 交互正确性
→ Dashboard 组合
→ 视觉保真
```

前一案例达到 `replicated`、`blocked` 或经人工确认的 `partial` 后，才开始下一
案例。不并行修改 cwtwb，不跨案例混合验收。

## 9. 状态

- `selected`：文章和主文件已经锁定；
- `partial`：只完成部分必要解题链；
- `replicated`：完整复刻并通过验证；
- `blocked`：被数据、Tableau 语义或验证环境阻塞。

`consumed` 与复刻状态分开记录：它只表示案例已经用于一次研究或迭代，后续选样
默认排除；它不代表已经完整复刻。

## 10. 停止条件

出现以下任一情况，应结束当前迭代并记录 `partial` 或 `blocked`：

- 文章与主文件无法建立可靠对应；
- 无法说明普通解法为什么失败；
- 原始 Tableau 解题链仍存在关键未知；
- 无法编写可判断成功与失败的测试；
- Tableau 验证环境无法确认语义；
- 为完成案例必须引入与当前问题无关的大范围改动。
