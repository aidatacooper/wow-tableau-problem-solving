# 2020 Week 43: expandable mobile KPIs

Article publication: 2020-10-22. Official challenge publication: 2020-10-20, WordPress post 4039. Challenge identity: 2020 Week 43. Official source: https://www.workout-wednesday.com/2020-week-43-mobile-dashboard-challenge/ . The article HTML publication timestamp agrees with the archived article manifest.

The author uses one locked Superstore Hyper extract and eight worksheets. Four dual-axis KPI rows combine a grey bar with right-aligned numeric value and a left Gantt label containing the metric name and a plus/minus icon. Four continuous monthly bar worksheets use a baseline date in 2019 to combine matching calendar months across all years. SALES and PROFIT sum source order-line values; MARGIN divides total profit by total sales; CUSTOMERS counts distinct customer IDs independently at whole-dataset and month grains.

An unrestricted string parameter, Selected Measure, initially contains the empty string. A per-KPI calculated source field returns its metric name when closed and an empty string when already selected. Four on-select parameter actions toggle the state. The monthly worksheets filter a dimension equal to this parameter to their own metric. Thus exactly one monthly chart can be populated, or all four can be empty. Four True-to-False self-filter actions remove selection highlighting; action events and source/pane binding are verified from the artifact, without claiming browser clicks.

The original 400x600 dashboard uses a vertical flow alternating the four KPI sheets and monthly chart sheets. The author explicitly removed the generated Phone layout because it retained empty chart space. This replica also uses the narrow default layout and does not add or claim a tested Phone layout. REST parameter states cover the empty default and all four expanded metrics. The capture plan exports all eight business worksheets from both workbooks in every state. Numerical verification requires all four KPI values in every state and all 12 monthly values for every active replica chart. The author Margin worksheet returned an empty REST CSV in two complete capture rounds despite its visible 12-bar Margin image. This precise source limitation is recorded separately: the empty author Margin export provides no numerical proof. The replica Margin values must independently match the locked Hyper oracle; the source Margin image and native formula provide comparison evidence. All other active author charts must have complete 12-month CSV coverage. Empty inactive charts are expected and provide no metric proof.

The continuous monthly date axis uses the original first-letter date format and two-month major ticks originating on 2018-12-01. Metric axes are hidden. Original fixed sales/profit/margin axis ranges reserve room for labels. Both KPI panes carry the toggle source field and deselection fields, and the verifier checks those bindings and actions independently. The builder begins with TWBEditor("") and reads only the locked business extract; it does not import source workbook XML or use it as a template.

An analysis-only comparison/export copy removes only hidden flags from worksheet windows. The provenance file binds original and comparison package SHA256, verifies business XML identity, and lists every unchanged package member. Layout and all business calculations remain unchanged.

Released SDK baseline construction and independent raw/native checks pass. The first Cloud capture revealed default month-grain date-axis conversion; the corrected builder explicitly uses EXACTDATE(Baseline Date). The next capture revealed colliding Sales/Profit horizontal labels and oversized KPI rows. The final candidate restores 52-pixel fixed KPI rows and explicit -90-degree value-label orientation for Sales/Profit. The final fresh Cloud capture verified all five parameter states, all ten paired images, all 80 worksheet CSV files and the complete raw-data oracle. The final result is acceptable_delta within the declared REST/artifact scope, with the explicitly unavailable author Margin numerical export described above. See evidence/visual-review.md for the frozen artifact hash and remaining visual differences. Browser selection, hover and actual mobile behavior are outside the requested REST/artifact acceptance scope.
