# Profit lozenges with native Measure Names

Article date: 2020-12-11. Challenge identity: 2020 WW50. Donna's 800 x 900 dashboard aligns seventeen subcategories by descending SUM(Profit). Two synchronized Measure Values axes overlay circles and thick rounded lines between SUM(Sales) and calculated Cost=SUM(Sales)-SUM(Profit). Sales circles are dark green or magenta by positive/negative profit, Cost is white and a duplicated Cost circle creates a grey rim. The line behind them is pale green or pink. Positive labels sit on the circle pane's selected endpoint; negative labels use the first line endpoint. Both profits use currency formatting; only losses carry a minus sign. A secondary Data worksheet exports Sales, Cost and Profit independently.

The locked Hyper extract contains all 9994 facts with Sub-Category, Sales and Profit. The builder begins with TWBEditor("") and adds calculations, native Measure Names/Measure Values panes, palettes, sizes, labels and layout through public SDK methods. It cannot open an author archive. Publication comparison changes only hidden attributes on existing worksheet windows.

The released SDK could add both color fields to a marks pane, but could not serialize their six-member compound palette. Public set_compound_color_palette resolves Measure Names expressions and boolean values into a native multibucket palette. Its synthetic regressions contain no author data or workbook. A second released limitation rejected categorical size_style; its generic catsize extension resolves virtual Measure Names as nominal and preserves the original Cost/Sales/Cost-copy order with a 0.875774 to 1 size range. This restores the white Cost center and larger grey rim without separate synthetic marks. Business data remains unchanged, including the three loss-making categories Bookcases, Supplies and Tables.

Acceptance independently aggregates every fact and checks Data and Viz exports at five states: default, complementary sixteen-subcategory (excluding Copiers) and Copiers-only partitions, four furniture categories, and three negative-profit categories. Default author Viz CSV actually returns only Copiers, even when an all-domain filter is requested; it is explicitly recorded as incomplete coverage. The earlier 8+9 partition containing Copiers still exported only that selected category and was rejected. The final 16+1 partitions must each return every requested real measure cell and jointly cover all seventeen categories. Primary Measure Values exports are checked within 0.000001; currency-formatted tooltip fields allow at most 0.51 rounding error. Full-precision raw aggregates are recorded separately. CSVs must contain every requested subcategory and real measure cells. Conditional labels, synchronized axes, compound palette, circle/line encodings, fixed geometry and sort contracts are inspected in the generated workbook. Paired Cloud images establish layout with documented small visual differences. No hover execution is claimed.

The final build uses immutable SDK df8c2a52cd48800fa0a43d936f6946d318f5b953, validated by 844 tests with 25 skips. Positive and negative label alignment is set through public worksheet pane cell styles; currency axes use the source $50,000 format. The author native Line pane has no explicit Path encoding, so its implicit Measure Values line structure is preserved. Rejected earlier captures are archived with their artifact identities and reasons.
