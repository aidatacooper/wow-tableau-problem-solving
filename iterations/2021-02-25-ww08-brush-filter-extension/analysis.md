# Brush Filter Extension — 2021 WW08

Article date 2021-02-25; official challenge date 2021-02-23 (WordPress post 4586). The task's central feature is the actual Starschema sandboxed Brush Filter extension, alongside five borough monthly trends.

The original extracted Hyper contains 158,923 date/borough records. Its bytes are locked without replacing the source data. Every Created Date is non-null, so the public calculation `COUNT([Created Date])` is independently proved equivalent to the author's native table-object row count. The chart excludes Unspecified, limits the continuous month domain to January 2010–February 2021, and presents 134 months for each of five boroughs: 670 visible cells. Start/end counts are nested month-addressed window calculations partitioned by borough; each line's color reflects endpoint increase, decrease or no change. Overall start/end month title calculations retain the source table-across behavior.

The builder creates an empty workbook and declares all fields, native marks, sorts, filters, titles and dashboard zones using public APIs. It loads only the locked Hyper in inputs. It never imports author XML or reads an author workbook. A computed rank sort restores the author's borough order without a case-specific SDK interface.

The dashboard embeds the real extension `com.starschema.extension.brushfilter.sandboxed`, version 0.1.0, at `https://extensions.tableauusercontent.com/sandbox/brush-filter/index.html`. The structured public manifest preserves its author, localized name, description, minimum API version 1.1 and configure menu. Native settings preserve the source colors, MONTH(Created Date), AGG(# of Sightings), and worksheet index 0. Only by Borough belongs to the dashboard, so index 0 is bound correctly. A blank layout spacer reserves the extension region; the actual extension zone renders there. This is not a native brush substitute.

The released fe9 baseline lacked `add_dashboard_extension`. The SDK now exposes a generic structured extension-manifest/settings primitive with author-free synthetic regression coverage. Source manifest identity and settings are analyzed as configuration; the builder does not read or concatenate their XML.

The real extension renders in the actual Tableau Cloud REST image export. Public extension JavaScript reveals an upstream aggregation issue: for repeated dates it increments `priceee`, while `drawBrush` consumes the original y-axis value. Consequently the overview reflects the first summary-data borough for each date, rather than a correctly summed NYC total. The reconstruction preserves the real extension and restores the author's borough order; this overview must not be described as independent proof of all-borough totals. Full chart CSV, independently checked against raw records, supplies numerical acceptance.

The native source Borough filter is exclusive. A REST Borough=BROOKLYN override therefore excludes Brooklyn, rather than selecting only Brooklyn. That state also exposes six Unspecified cells previously excluded by the default filter, giving 542 cells. The verifier explicitly checks the effective domain and each raw count/classification. REST requests verify data states and configuration; they do not prove a mouse drag occurred. No browser brushing, selection, or clearing action is claimed.

For that Borough override, both source and replica dashboard REST images retain the default five-borough layout and February 2021 title. The worksheet CSV applies the override and returns 542 cells, including the September 2020 global end-month title. This state proves filtered worksheet data/calculation behavior through CSV, while image review proves the default dashboard and extension rendering. Filtered dashboard visual response is not claimed.

Author files remain in ignored scratch analysis. Only worksheet window visibility changes in the comparison export, recorded with hashes. Final acceptance must use matching final SDK/artifact provenance and fresh REST images/CSV; observed visual differences are recorded after paired review.
