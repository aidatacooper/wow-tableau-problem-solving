# WW15 dynamic week start

Article date 2020-04-10; official 2020 WW15 publication 2020-04-08 (WordPress post3612). The dashboard uses one Line worksheet in1300x700. Two parameters determine an ending date and number of prior weeks. Each selected week begins six days before its ending date; every historic week maps to seven chronological weekday positions of the selected week. Latest week is#19626b and prior weeks#d6d6d6. Each daily mark sums all locked Superstore facts. Missing dates must produce zero, no sales text and their actual date in the tooltip.

The independent oracle reads the locked 9,994-row original Hyper. Analysis groups those facts by day using math.fsum, adds the full 2016–2019 Gregorian calendar with zero for absent dates, and saves locked daily-calendar.csv plus a typed 1,461-row Hyper. The verifier checks every derived daily value and the original sales total 2,297,200.8603, then verifies the Hyper against the CSV and its packaged hash. The empty-workbook builder reads only the derived calendar Hyper and calls public SDK APIs. It derives week starts with a nonnegative modulo offset, equivalent to the original seven DATETRUNC cases, and retains native LOOKUP/IFNULL completion plus previous/next missing-date tooltip logic. This author tooltip method assumes no two adjacent missing dates; independent grids expose all missing dates so Cloud review can detect any limitation. The builder reads the locked derived calendar Hyper, never the author workbook.

Four REST states cover Friday-start default11weeks, Monday-start5weeks, Tuesday-start2weeks and current-week-only. A complete daily-fact oracle builds all7*(prior+1) cells including absent dates; full Viz CSV must prove all cells, not merely screenshot-visible marks. Tooltip fields and parameter domains are artifact contracts; no click or hover execution is claimed. Original-export analysis copy only removes hidden worksheet-window flags. Source/data/article hashes are locked.

The released baseline built the daily view, but a Monday-ending REST state exposed a missing-date defect: both weeks had no Friday facts, so the replica exported only 12 of 14 required cells while the author exported all 14. LOOKUP alone cannot create an entirely absent date column. The original native table declares show-full-range for the raw Baseline date field. A reusable configure_worksheet_domain_range public API now emits that date-range completion contract; synthetic tests cover exact-date validation, raw references, duplicate removal, replacement, clearing and MCP forwarding. Baseline API failure and the 12-versus-14 comparison are recorded in evidence/sdk-domain-range-baseline.json. The final builder also uses explicit exact-date ordinal expressions rather than Tableau's default MONTH date grain. The final paired Cloud images and all eight full-grid CSVs pass acceptance with released SDK 56377c5b170f0df1f5cd853fc483de26962dfed1. The complete replica grids have 77, 35, 14 and 7 cells. Title weekday dimensions are explicit detail/LOD encodings, preserving their rendered values across all four parameter states. Layout preserves the source title, top-right parameter cards, seven day headings and two-row attribution/link footer. The result is acceptable_delta; evidence/visual-review.md binds the reviewed artifact hash and records the remaining typography/padding differences and the current-only source limitation.

The current-only REST state exposes an author limitation: the first selected day, Friday 2019-10-18, has no facts and falls before the native domain minimum, so the author exports only six dates. The replica deliberately fills that missing leading day with zero and validates all seven cells. The author-only six-cell exception is narrowly declared in the verifier; all other source grids and every replica grid remain complete. A conditional Tooltip Sales calculation suppresses the numeric zero when the explicit no sales message is displayed. No browser hover is claimed.
