# Counties within a distance

Article date: 2020-09-06. Official WordPress post 3969 explicitly identifies 2020 week 36 and was published 2020-09-02. The original data filename says WW26, but this typo is preserved only as a source file identity.

The input has 3,142 county records dated 2020-08-26. The build preserves that fixed snapshot. Initial Selected County membership is All, matching the original. A deterministic CSV projection of original County, State and State fields initializes membership via public add_set. Its hash is locked and its entire membership is independently compared with raw Hyper.

When exactly one county is selected, FIXED average latitude/longitude produce its start point and Tableau DISTANCE in miles limits the maps, case count bars and resource bars. When more than one county is selected, the source deliberately includes all counties and ignores radius. A native dropdown set control is required: the released SDK rejected set_control, documented in sdk-baseline.json; the candidate adds a general native setMembership zone/card API.

The three maps show continental states, Alaska and Hawaii separately. Hospital-bed percentile is an ascending RANK_PERCENTILE table calculation over county marks within the individual filtered map; it is not necessarily the same percentile as the all-county case bar. County shapes are colored with green-gold, while state outlines use the second native map pane. Resource utilisation is the sum of hospital beds, ICU beds and estimated ventilators, not cases divided by capacity.

REST has no validated method in this workflow to change native set membership. Acceptance therefore captures default All plus 50/250-mile parameter states, verifies the entire exported county/resource marks, and checks the set control, MAKEPOINT/DISTANCE, membership, filtering and table-calculation contracts. An independent single-county great-circle oracle records 0/50/100/250/500-mile scenarios. These calculations are independent checks, not a claim that Tableau executed the selections, and spherical distance is not a claim of exact ellipsoid agreement. No browser selection, hover or click is executed.

All six source worksheets are exposed only through worksheet window visibility changes in the author comparison copy. Source formulas, filters, dashboard and data remain unchanged. The builder only reads extracted inputs and public SDK APIs after TWBEditor(""). All three final paired Cloud states, six PNGs and 36 complete worksheet CSVs passed independent numeric and visual acceptance with documented acceptable_delta in evidence/visual-review.md.


Native rank diagnosis: the original uses an independently identified table-calculation instance for Field addressing over county/state dimensions. Initial SDK maps kept an unsuffixed User instance and exported every non-null percentile as 100%; counts and resource sums were correct. Matching the source base Columns direction did not fix this. Root-authorized scratch-only diagnostics of the SDK-generated artifact isolated the calculation-instance context: variant A changed only that instance identity and passed all 5 Hawaii and 29 Alaska county/resource/percentile checks; geographic metadata parity and removal of the state overlay still failed. These experimental XML edits are analysis evidence, never formal build logic. The formal case now calls the generic public table_calc_context=True option on all five rank-bearing charts after SDK synthetic regression tests. Context identities are generated by the SDK, with no case-specified suffix. Static verification binds each actual instance to its Field addressing, colour styles, dashboard legend and Measure Names entries; full Cloud revalidation is required. See evidence/sdk-table-calc-context-gap.json.

The first candidate context API assigned the same local context identity to all five worksheets despite different Field addressing vectors. Its quick probe still failed. The refined generic SDK allocator makes contexts unique across the workbook for each calculation-instance family, preserving an existing identity when reconfiguring the same worksheet. The verifier rejects duplicate rank identities across the five business/diagnostic charts. This identity allocation is SDK-owned, with no case-specific numerical IDs. Final full worksheet exports passed global Cases/Data ranks and separate continental/Alaska/Hawaii partitions.
