# WW24 Three versus fourteen day averages and latest trend

The article was published on 2020-06-12. The official challenge was published on 2020-06-09 (WordPress REST post 3753). The dashboard combines a state and county search, latest trend summary, county map, daily cases with a selectable moving-average line, and a county comparison table for the selected state.

The locked Hyper contains 422,143 rows: 3,037 county histories with 139 daily records from January 21 through June 7, 2020. The source extract excludes NULL county records. The packaged data already contains no NULL county rows, and its latest date is June 7. A conditional FIXED maximum date and Valid County worksheet filters preserve this boundary using public APIs.

Both moving averages use the preceding two or thirteen records plus the current record and ignore NULL values. Increase requires the three-day average to exceed the fourteen-day average; equality counts as DECREASE. Consecutive trend days use FIRST, LOOKUP and PREVIOUS_VALUE, resetting when the binary direction changes. The latest-date filter remains a LOOKUP table calculation applied after the historical calculation. The default Tennessee - Davidson selection on June 7 has 124 new cases, 6,156 reported cases, a three-day average of 108.3333, a fourteen-day average of 101.7857, and a one-day INCREASE.

The independent verifier computes all county histories from the raw Hyper. Cloud CSV acceptance requires all counties of the selected state with four latest-date metrics, every selected county daily bar and line date from March 8 through June 7, and the BAN trend direction and consecutive-day count. Full table CSV is required even when the dashboard viewport displays only its upper rows. Default, three-day, Tennessee - Campbell and California - Los Angeles REST states exercise the selectors and geographic context. No browser click or hover is claimed.

The map uses calculated County and State aliases, their public geographic roles, and United States geocoding context. Map Colour combines the source two-field palette into an equivalent calculation: selected increasing county red, selected decreasing county green, all other counties white. Selected Order preserves the selected-county-first group, followed by descending reported-case sorting. Display Date is separate from the ISO Report Date so exported dates remain auditable.

The builder starts with TWBEditor("") and reads only the locked Hyper through public SDK APIs. Author comparison workbooks remain in scratch and expose worksheet windows only; export provenance confirms that their formulas, data and dashboards remain unchanged. Acceptance IDs are ww24-history-oracle, ww24-latest-trend, ww24-geographic-contract and ww24-cloud-states. Cloud visual and data review is pending.

The first Cloud capture exposed a case construction error: bare date captions acquired the SDK default MONTH grain, so the late date filter eliminated BAN, Map and Table marks. The correction uses the existing public bracketed `[Report Date]` reference for exact discrete days, and continuous EXACTDATE for the bar/line axis without a second discrete date partition. Nested table-calculation contexts now list only the actual dependency closure. This is a correction to case API use, not an SDK capability gap.

The Bar&Line worksheet applies its physical March 8 date filter before moving-average calculations. Its independent oracle therefore recomputes from the truncated sequence; the first Davidson March 8 fourteen-day average is 1. The latest-date table and BAN retain January 21 onward histories. These distinct calculation scopes are verified separately; a post-calculation truncation would incorrectly yield 0.0714286 for the first plotted average.

The first exact-day correction passed all 24 paired CSV exports, proving complete latest tables, BAN trends and all 92 plotted dates. Visual review still found truncated column headers, reversed county ordering and a blue/orange line palette. The subsequent refinement leaves those verified calculations unchanged. A Line Direction alias scopes the colored moving-average line to one table-calculation context; the original direction remains available for BAN/map/table. The table uses source-order measures and multi-line native aliases with explicit header height and font. A hidden ascending negative FIXED county historical-case sum reproduces the author's descending historical reported-case ordering within the selected-county group. The numeric moving-average control now includes the author's current-value alias. These are public API case changes, and their fresh Cloud images are still required for final visual acceptance.

Fresh fit-width capture confirmed all four table columns were visible, but invalid numeric format strings without Tableau's `n` prefix left full-decimal values and hash placeholders. Source analysis identifies the native numeric code `n#,##0;-#,##0`; the final builder applies this exact legal code through public field/cell formatting. Calculations remain full precision; no ROUND wrapper or altered moving average was introduced.

Final Cloud artifact `522910fd8eed51d10a2a5c0d9945b82aa7f9f38dc507739651e7f3fac3bfacd0` passed all 24 independent CSV checks and review of all eight paired PNGs. Four table metrics and their full headers are visible in every state; legal native numeric formatting removes hash placeholders while preserving the original full-precision calculations.
