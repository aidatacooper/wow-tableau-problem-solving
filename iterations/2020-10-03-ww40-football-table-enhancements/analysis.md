# NFL rushing table enhancements

Article 2020-10-03; official WW40 date 2020-09-30 (WordPress post 4012). The original locked Hyper has 40736 rushing plays, 556 distinct players, and seasons 2017-2019. Independent raw aggregation calculates Carries, Yards, Avg YPC and TDs for every player and player/season group. Carries counts nonnull player IDs, equivalent to original physical-table row count; the oracle checks player IDs are nonnull.

The empty-workbook public API build preserves the integer pLevel toggle and selected-player parameter. The season label appears only for the expanded selected player. Four header panes show independent sort choices and selected colours; virtual Measure Names parameter action selects Measure1-4, position FB/P chooses descending/ascending, and a separate header action resets the page. Native parameter actions and true-to-false deselection filter mappings are checked through generated contracts, not browser clicks. Page controls clamp prior/next state using the original FLOOR(COUNTD(player)/pageSize)+1 total-page calculation.

The original uses native computed sorting on raw player ID before nested INDEX. Released shelf sorting produced incorrect page membership despite correct metric values. The enhanced public layered API uses sort_mode="computed" with the source four row layers and aggregate sort expression. Cloud must prove exact player sets, and expanded coverage includes every raw season of the selected player plus the full independently ranked collapsed page. Table calculations preserve original Columns addressing and nested Page/Index contexts. The default shows collapsed players; REST parameters additionally cover page two, expanded top player 10638, yards ascending, average yards per carry descending and the final touchdowns-sorted page.

An exact cbe200a git archive was imported in an isolated subprocess for the released SDK baseline despite the shared environment temporarily being editable. Initial raw/native checks passed, but Cloud validation exposed case construction bugs and the later computed-sort SDK gap; blocked evidence is retained instead of claiming the initial local check was accepted. Requested Cloud exports cover every metric on their bounded pages; they do not represent all556 roster rows in a single CSV. The independent raw oracle still covers the complete roster and season groups. Paired source comparison exposes existing hidden worksheet windows only; no source formulas, layouts or data are changed.

Header CSV verifies all twelve measure/direction marks, selected direction, and reset-to-page-one binding. Page CSV verifies current/total pages and clamped previous/next target values, not merely nonempty controls.

The Set Level action reads the per-player DD Level actually encoded on Table marks, matching the author. It must not read global Max Level: with another player expanded, a collapsed clicked player has DD Level=1 while global Max Level=2. The verifier now checks every action source instance exists on its worksheet, resolves its declared column, and targets the correct real parameter; true-to-false deselection and auto-clear contracts are also checked. Earlier REST-only passing exports did not prove this binding, and the rejected action source is preserved in action-source-baseline.json.
